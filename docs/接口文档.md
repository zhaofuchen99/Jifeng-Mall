# 基于 Spring Cloud 的 B2C 微服务秒杀商城 — 接口文档

> 本文档依据《详细设计说明书 V1.0.2》第 4/8 章，并结合当前后端实现整理。供前端（PC 商城 / 后台管理系统）对接使用。所有接口经网关统一暴露。

| 项目 | 说明 |
| --- | --- |
| 网关地址 | `http://网关IP:8888`（开发环境） |
| 协议 | HTTP（开发）/ HTTPS（生产） |
| 数据格式 | 请求与响应均为 JSON |
| 上传接口 | multipart/form-data |

# 1 通用约定

## 1.1 统一响应结构

```json
{
  "code": 200,
  "success": true,
  "msg": "success",
  "data": { }
}
```

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| code | int | 状态码，200 成功，其余见错误码 |
| success | boolean | 是否成功 |
| msg | string | 提示消息 |
| data | object/null | 业务数据 |

## 1.2 分页约定

- 请求参数：`pageNo`（默认 1）、`pageSize`（默认 0 = 查询全部）
- 响应 `data` 为 `PageInfo`：

```json
{
  "code": 200, "success": true, "msg": "success",
  "data": {
    "list": [ "..." ],
    "total": 36,
    "pageNum": 1,
    "pageSize": 12
  }
}
```

## 1.3 认证

- 除「公开接口」外，请求头需携带 `Authorization: Bearer {token}`
- 网关解析令牌后向后端注入请求头（业务服务使用）：
  - `X-User-Id`：用户/会员主键
  - `X-User-Name`：登录账号（user 为 username，member 为 account）
  - `X-Audience`：admin / member

## 1.4 错误码

| code | 含义 |
| --- | --- |
| 200 | 成功 |
| 400 | 参数错误 |
| 401 | 未登录或令牌失效 |
| 403 | 无权限 |
| 404 | 资源不存在 |
| 429 | 请求过于频繁/限流 |
| 500 | 系统内部错误 |
| 7001 | 库存不足 |
| 7002 | 未到秒杀时间或已结束 |
| 7003 | 已参与过该秒杀/超出限购 |
| 7004 | 秒杀已售罄 |
| 7005 | 订单状态不允许该操作 |

# 2 网关路由

| 路由前缀 | 目标服务 | 是否需要登录 |
| --- | --- | --- |
| `/api/brands/**` | brand-api | 需 RBAC |
| `/api/categories/**` | category-api | 需 RBAC |
| `/api/goods/**` | good-api | 查询(GET)公开，写需 RBAC |

| `/api/member-addresses/**` | member-address-api | 需会员 |

| `/api/carts/**` | cart-api | 需会员 |
| `/api/orders/**`、`/api/order-items/**` | order-api | 会员/后台 |
| `/api/users/**` | user-api | 登录公开，其余需 RBAC |

# 3 前台接口清单（PC 商城 / 会员端）

## 3.1 会员认证

```

{ "goodId": 3, "qty": 1, "addrId": 5, "memberAccount": "member01" }

{ "id": 100, "orderNo": "1891...", "totalPay": 2999.00, "status": "待付款" }
```

### 秒杀抢购详细定义
```
POST /api/seckills/grab
请求：{ "seckillGoodId": 11 }
响应（提交成功，结果异步）：
{ "code": 200, "success": true, "msg": "抢购提交成功，请等待结果",
  "data": { "code": 200, "msg": "抢购提交成功，请等待结果", "orderNo": "1891...", "success": true } }
```
> 抢购结果异步创建订单，前端可凭 `orderNo` 轮询 `GET /api/orders/member-account/{account}` 查看订单是否生成并支付。

# 5 关键流程（供前端参考）

## 5.1 登录认证流程

```
1. 前台：POST /api/members/login 或 /api/users/login → 获得 token
2. 后续请求头携带 Authorization: Bearer {token}
3. 网关校验令牌，非法/过期返回 401 → 前端跳转登录并回跳原页面
```

## 5.2 下单流程

```
1. 确认购物车/立即购买 → POST /api/orders/create（需登录）
2. 返回待付款订单 + orderNo
3. POST /api/orders/{id}/pay → 模拟收银台
4. POST /api/orders/{id}/pay/confirm → 已支付
5. 待付款订单 30 分钟未支付 → 网关/服务端自动关单并回补库存（RabbitMQ 延时消息）
```

## 5.3 秒杀流程

```
1. 查看秒杀活动 → GET /api/seckills/active / /api/seckill-goods/seckill/{id}
2. 点击立即秒杀 → POST /api/seckills/grab（需登录）
3. Redis Lua 原子扣减（防超卖）+ 记录已抢（防重复）
4. 发 RabbitMQ 异步下单 → 返回 orderNo
5. 前端凭 orderNo 轮询 GET /api/orders/member-account/{account} 查看订单生成并支付
6. 秒杀订单 30 分钟未支付自动关闭，回补秒杀库存
```

> ✅ **秒杀库存一致性（已实现）**
> - **防超卖（双保险）**：Redis + Lua 原子扣减；DB 侧成交时以条件更新兜底
>   `UPDATE seckill_good SET sold=sold+qty, stock=GREATEST(stock-qty,0) WHERE id=? AND stock>=qty`
>   （异步下单消费者执行，库存不足则不成交，防超卖）
> - **抢购登记**：抢购成功将 `seckill:order:{seckillNo} = {seckillGoodId}` 写入 Redis
> - **异步下单幂等**：消费者与 order 服务均以 `seckillNo` 为准，同一秒杀流水号仅创建一张订单，MQ 重投不重复下单 / 不重复扣减；下单失败自动回滚本次扣减后重试
> - **超时关单回补**：秒杀订单超时（30 分钟）由 order 服务关单；order 检测 `seckillNo` 非空时调用秒杀服务 `POST /api/seckills/restock`，同步回补 Redis 秒杀库存 `seckill:stock:{seckillGoodId}` 与 `seckill_good.stock/sold`；秒杀订单**不**回补普通商品库存 `good.qty`（下单时未扣减）
> - **库存预热**：秒杀服务定时任务扫描启用且未结束的活动，将各秒杀商品剩余库存预热到 `seckill:stock:{seckillGoodId}`——活动未开始强制刷新，进行中仅缺失时补齐（不覆盖实时扣减）；间隔见 `jifeng-mall.seckill.preheat-interval-ms`（默认 60 秒），另保留首抢懒加载兜底
