### 标准 5：性能达到 NFR-001 ⚠️ 部分达成

> 以压测报告为准。

| 结论 | 数据 |
| --- | --- |
| 并发 ≤ 50 | ✅ 达标，P95 = **75 ms**（阈值 100 ms），吞吐 672 req/s |
| 并发 = 100 | ❌ 不达标，P95 = 139 ms |
| 并发 = 200（同步洪峰） | ❌ 不达标，P95 = 420 ms |

**判定为「部分达成」的依据**：NFR-001 的原文是「秒杀抢购提交 P95 < 100ms」，
未限定并发度。按最保守的读法，单实例开发环境下**并发 100 以上即不满足**。

延迟随并发近似线性上升、单笔 P50 仅 14 ms，说明瓶颈在**请求排队**而非单笔处理。
本机为单实例 + 压测端与服务同机竞争 CPU 的开发环境；
生产应按 NFR-003 多实例部署，并在独立压测机上复测。

> ⚠️ 另有一条实测发现：同脚本同参数重跑，P95 在 420 ms 与 541 ms 之间波动（**差 29%**）。
> 这本身说明该数据的精度**不足以支撑生产容量规划**，只能用于横向对比与验证正确性。
> 详见 `docs/测试报告.md` §6.3。

### 3.2 自动化验收（推荐）

```bash

# 2) 跑全部断言（打 Nginx 生产形态，与浏览器同路径）
cd tools/verify
export JIFENG_BASE=http://<host>:8090
python3 rbac_verify.py            # 15  越权拒绝
python3 admin_verify.py           # 53  后台全流程
python3 banner_verify.py          # 26  首页轮播
python3 member_password_verify.py # 33  密码相关
python3 region_verify.py          # 42  地区管理
python3 fe_verify.py              # 43  前台全流程
python3 owner_verify.py           # 23  数据归属
python3 refund_verify.py          # 43  订单退款
python3 order_timeout_verify.py   # 17  超时关单兜底（约 4 分钟）
python3 delete_reference_verify.py # 21  删除禁引校验
python3 login_guard_verify.py     # 24  防爆破（约 2 分钟）

# 3) 并发压测（验收标准 3 的直接证据）
```

**预期结果：第 2 步合计 340/340，第 3 步 6/6。**

> 哪些还需要在真实环境中重新验证。
